# 专名表与命名规则

> 用途：**所有专名的唯一权威**。写文本、写代码、做本地化前先查；新专名先登记再使用。
> 规则：一个概念一个译名；官方已有的用官方译名；官方没有的由本表锁定，不得随文案变动。

## 4. 命名规则（代码）

| 对象 | 规则 | 示例 |
|---|---|---|
| 命名空间 | `Calamitytwinklefragment.<目录路径>` | `Calamitytwinklefragment.Content.NPCs.BossGod` |
| 物品类 | 英文 PascalCase，**不加** `Item` 后缀 | `DeepRed`、`FinalPray` |
| 碎片类 | `Fra` + 英文物名 | `FraMoldyPaper`、`FraArmsOrder` |
| Boss 类 | 英文专名，不加 `Boss` 后缀 | `LunaGoddessLunatica`、`LordOfPutrescence` |
| 弹幕类 | `<Name>Projectile`（历史遗留可用 `Proj`） | `TerminalSoundWave` |
| Buff 类 | `<Name>Buff` | `BlazingDash`（历史遗留无后缀） |
| Debuff 类 | `<Name>Debuff` | `EternalDecayDebuff` |
| 贴图 | 与类名同名，放在同类目录 | `Content/Items/Fragment/FraMoldyPaper.png` |
| 本地化键 | 与类名一致 | `Items.FraMoldyPaper.DisplayName` |
| 文件名 | 与类名一致；**新增文件一律英文** | 见 `13-pitfalls.md` 关于中文目录 |

> 历史遗留（如 `Content/Buff/Debuff/硫磺火.cs`、`Projectiles/spine表/`）不强制改名，但**新增内容不得再建中文目录/文件名**。

## 7. 新增专名流程

1. 查本表与 `00-canon.md`，确认不是已有概念的重复命名。
2. 判定状态：`[正史]` / `[半官方]` / `[原创·草案]` / `[原创·待定]`。
3. 填写：中文、英文、类别、状态、首次出现位置、一句话说明。
4. 英文名须符合英语构词，不要拼音直译（除非是刻意的异域名）。
5. 同步更新所有已引用处；不要留下两个译名并存。
6. 若是神明/地名，补进 `02-gods.md` 或 `00-canon.md` 对应表。

## 8. 英文文案注意事项

- 官方英文名**首字母大写、不加冠词**：`Azafure`、`Ilmeris`、`Yharim`。
- 群体用复数：`the Azafurians`、`the Ilmerians`、`the Onyx Kinsmen`。
- 称号格式：`Providence, the Profaned Goddess`；中文 `普罗维登斯，灰烬女神`。
- 物品名：`Twinkle Fragment: Moldy Paper`（与中文 `吉光片羽：发霉的论文` 对应）。
- 不要音译中文专名（如「Mana Crusade」不是「Mana Jiaohujun」）。
